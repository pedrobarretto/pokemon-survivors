# Pokémon Survivors – agent guide

Browser survivors-like (Vampire Survivors–style) with Pokémon. Vite + TypeScript + Canvas 2D, no engine. Read `README.md` for the architecture map.

## Conventions

- **Functional TypeScript only.** Use plain data (types/records) and functions. No classes or `this`. Never use `any`. Prefer inferred types and `as const satisfies` data tables, and keep content data-driven (`src/data/*`, `MOVES` in `src/game/moves.ts`).
- The simulation mutates plain state for performance (hundreds of entities at 60 Hz), and that's fine. Keep hot loops allocation-light (see `retain`, the spatial grid).
- **The simulation is deterministic**: the server re-simulates ranked runs from their replay (`src/game/replay.ts`) and must land on the same bits. In `src/game` (and anything it computes from `src/data`) use the seeded rng, never `Math.random` or the clock; use `engine/dmath` (`dm.sin`, `dm.cos`, `dm.atan2`, `dm.hypot`, `dm.exp`, `dm.pow`, `dm.sq`) instead of `Math.sin/cos/atan2/hypot/exp`, `**` or `Math.pow`, which differ between JS engines; size hitboxes from `bodyOf` (data), never from loaded sprites. Anything new the shell does to a running game (a pick, a button) goes through `recordEvent` and gets a case in `resimulate`, and, for co-op, a `TickEntry` in `src/net/protocol.ts` applied in `stepTick` (`src/game/lockstep.ts`).
- **Co-op is lockstep on the same simulation**: every player simulates the same run; the play server only relays inputs. The game holds `players` by slot. Per-player code (moves, specials, Mega, a pickup's effect, damage taken) reads `g.player`, which `actAs` points at whoever is acting; world systems (enemies, spawns, pickups, map events, rifts) must never assume `g.player` and go through `src/game/players.ts` (`nearestPlayer`, `playerWithin`, `onAnyScreen`, `anchorPlayer`). Solo must stay bit-identical: a change that alters solo runs bumps `RULES_VERSION`.
- **Simulation ≠ presentation.** `src/game/*` must not touch the DOM or audio. Notify the shell by pushing a `GameEvent`; `main.ts` handles sounds, cries and toasts.
- **Pixel-perfect rendering.** The world is drawn at low internal resolution and integer-upscaled. Snap draw positions to whole pixels and use the hard-edged helpers in `engine/pixelart.ts`. New effect art is code-authored pixel strings (`render/art.ts`).
- **Two languages: pt-BR and English.** Every player-facing string lives in `src/i18n` (`pt.ts` is the reference; `en.ts` must match it key for key, and the type checker enforces it, down to one line per move upgrade). Read text with `t()` at render time, never at module load. Pokémon, move and item names stay in English (official names) and live in the data files.
- **Comments:** short doc comments above non-obvious functions. Don't comment every line, and keep comments in sync with the code.
- **Tests:** focused vitest tests for pure rules only (`*.test.ts`). No smoke or snapshot slop.
- **SEO/GEO copy** lives in static HTML so crawlers and AI chats can read it without JS: `index.html` (pt-BR, `/`), `en/index.html` (English, `/en/`) and `public/llms.txt`. When a feature changes what the game is (starters, bosses, counts), update all three.
- **Site pages** (`/pokedex/`, `/guia/`, `/novidades/`, `/legal/` and their `/en/` twins) are rendered at build time from `src/site` (wired in `vite.config.ts`) and read `src/data/*`, so the Pokédex and the guide's tables follow the data on their own. Their copy lives in `src/i18n/site` (`pt.ts` is the reference). Routes live in `src/site/routes.ts`, which also generates `sitemap.xml`. Add a `src/site/changelog.ts` entry when a player-facing change ships. `src/site/client.ts` must never import game code, so the game and the site never load each other's bundles.
- **Mobile matters:** many players will be on phones. Every UI must work with touch and on small portrait and landscape screens.

## Commands

```bash
npm run dev        # vite dev server
npm test           # vitest
npm run build      # tsc --noEmit + vite build (must pass before any PR)
npm run roster     # rebuild the wild horde (curated list in scripts/roster.mjs) from PokeAPI + SpriteCollab
npm run assets     # fetch sprites (add new dex numbers in scripts/dex.mjs; the horde comes from the roster)
npm run credits    # regenerate CREDITS.md (SpriteCollab artists) after adding species
npm run bodies     # re-measure sprite bodies (hitboxes) into sprites.generated.json; `npm run assets` does it too
npm run typecheck --prefix server   # the accounts API (server/), typechecked with the shared game code
npm run dev:play --prefix server    # the co-op relay on :3001 (set VITE_PLAY_URL=ws://localhost:3001/ws for the game)
```

- **Accounts are optional.** Guest play (the local save) is the default and must never wait on the network. `src/account.ts` loads Clerk on demand and syncs the save to the API in `server/` (Hono + Postgres, deployed on Dokploy, see `server/README.md`). The merge rules (`mergeSaves`, `applyPush` in `src/game/sync.ts`) are shared by both sides: when a save field is added, give it a merge rule there. Without `VITE_CLERK_PUBLISHABLE_KEY` and `VITE_API_URL` the account button doesn't show.

In dev builds, the browser console exposes `ps.run()` (current run state), `ps.startRun('squirtle')`, `ps.coop(['pichu', 'gible'])` (a local co-op run with bot teammates and no server, through the same lockstep path; a second argument sets your Pokémon), `ps.theme()` (music theme playing), `ps.biome('cave')` and `ps.weather('rain')` (both hold until the next scheduled change), `ps.terrain('cliff')` (walks you to the nearest `rock`, `tree`, `cliff`, `tower` or `lake`, standing 70 px south of it; a second argument sets that distance), `ps.spawn('chansey', 3)` (enemies in an arc ahead of you; a third `true` makes them shiny), `ps.dex()` (the saved Pokédex), `ps.pc()` (the Caixa do PC), `ps.card(partner?)` (the Trainer Card's share preview), `ps.unlockShiny(id?)` (unlocks a shiny starter, all without an argument) and `ps.event(kind, dx?, dy?)`, which places a map event (`altar`, `fountain`, `chest`, `spikes`, `bomb`, `meowth`) `dx`, `dy` px from the player (default 70 px to the right) and returns it, so you can tweak its `state`. Handy for staging screenshots: set `ps.run().game.hitstop = 9999` to freeze the simulation while it keeps rendering. For bosses: `ps.trio('beasts')` swaps the run's legendary trio (`birds`, `beasts`, `regis`) for the slots still to come, and `ps.boss('entei')` brings a boss in now with its wave entrance (an earlier wave's boss flees, as it would). For rifts and the endless mode: `ps.rift('kyogre')` steps into an arena (random legendary without an argument), `ps.portal()` opens a portal next to the player, `ps.victory()` shows the victory screen with the endless offer, `ps.endless(19.5)` jumps into endless mode at that minute and `ps.reaper()` calls Arceus now. For Mega Evolution (start a run with a line that has one, `MEGA_LINES` in `src/data/megas.ts`, e.g. `charmander`, `pichu`, `gible`): `ps.mega()` jumps to the final stage with the line's first Mega Stone and presses the Mega button (the transformation plays), `ps.mega('now', 'charizardY')` picks the Mega, `ps.mega('ready')` stops before the press and `ps.mega('stone')` drops the line's stones 40 px to the right, as a rift would (two side by side for Charizard, Raichu, Garchomp and Lucario). For eggs: `ps.egg('rare')` puts one in the incubator, `ps.walk(500)` walks the incubating eggs (all the way without an argument), `ps.hatch()` hatches every ready egg, `ps.hatch('gible', true, 2.8)` plays the hatching scene for a family (shiny, held at 2.8 s for screenshots), `ps.unlockFamily(id?)` unlocks one family or all and `ps.incubator()` opens the incubator. For missions and achievements: `ps.missions()` prints the current ones, `ps.mission(i, n?)` sets mission `i`'s progress (dailies 0-2, weeklies 3-4; default one short of done, so the next run completes it), `ps.completeMission(i)` completes and pays it, `ps.date('2026-10-19')` moves the missions' clock to that local day (`ps.date()` goes back to now), `ps.unlockAchievement(id?)` unlocks one achievement or all, and `ps.resetProgress()` wipes missions, achievements and the title. For the Surto do dia and the Poké Mart: `ps.outbreak('gastly')` holds that outbreak instead of the day's until the page reloads (no argument goes back; it plays from the next run and the title shows it), `ps.item('lure', 3)` puts items in the Bag, `ps.money(20000)` adds ₽ and `ps.unlockStyles()` owns every frame, background and wallpaper. For invites and Mystery Gifts: `ps.invite('ash', 'Ash')` lands as a guest invited by @ash (the title shows the invite banner without asking the API; needs `VITE_CLERK_PUBLISHABLE_KEY` and `VITE_API_URL`, any values do) and `ps.gift(kind, arg?, why?)` lands a gift as if a sync brought it: `ps.gift('egg', 'friend', 'ash')` (`why`: the inviter's handle, or a number of friends brought), `ps.gift('coins', '500')`, `ps.gift('title')` (Ambassador), `ps.gift('style', 'ambassador', 3)` (a frame) and `ps.gift('shinyHatch', 'munchlax')` (plays the hatching scene on the title). For the Desafio do dia: `ps.challenge()` opens its screen and returns today's challenge, `ps.challenge('play')` starts it, `ps.challenge('done', 754)` marks this device's official attempt as made (the screen then says practice) and `ps.challenge('reset')` forgets it; `ps.gift('ribbon', 'gold')` lands yesterday's ribbon as a Mystery Gift.

## Assets

Pokémon sprites come from PMD SpriteCollab (`sprite/<dex>/` has Walk/Idle/Hurt; shiny forms live under `sprite/<dex>/0000/0001/`). Portraits also come from SpriteCollab and cries from PokeAPI. They are downloaded by `scripts/fetch-assets.mjs` into `public/assets/pokemon/<dex>/` and indexed in `src/data/sprites.generated.json`. SpriteCollab is CC BY-NC 4.0 with per-artist credit, so keep `CREDITS.md` in sync (`npm run credits`).
