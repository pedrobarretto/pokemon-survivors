# Pokémon Survivors – agent guide

Browser survivors-like (Vampire Survivors–style) with Pokémon. Vite + TypeScript + Canvas 2D, no engine. Read `README.md` for the architecture map.

## Conventions

- **Functional TypeScript only.** Use plain data (types/records) and functions. No classes or `this`. Never use `any`. Prefer inferred types and `as const satisfies` data tables, and keep content data-driven (`src/data/*`, `MOVES` in `src/game/moves.ts`).
- The simulation mutates plain state for performance (hundreds of entities at 60 Hz), and that's fine. Keep hot loops allocation-light (see `retain`, the spatial grid).
- **The simulation is deterministic**: the server re-simulates ranked runs from their replay (`src/game/replay.ts`) and must land on the same bits. In `src/game` (and anything it computes from `src/data`) use the seeded rng, never `Math.random` or the clock; use `engine/dmath` (`dm.sin`, `dm.cos`, `dm.atan2`, `dm.hypot`, `dm.exp`, `dm.pow`, `dm.sq`, `dm.round`) instead of `Math.sin/cos/atan2/hypot/exp/round`, `**` or `Math.pow`, which differ between JS engines (Safari's JIT rounds 0.49999999999999994 up; `src/engine/dmathGuard.test.ts` fails on any of them in the sim); size hitboxes from `bodyOf` (data), never from loaded sprites. Anything new the shell does to a running game (a pick, a button) goes through `recordEvent` and gets a case in `resimulate`. A change that makes the same inputs end elsewhere bumps `RULES_VERSION` (`replay.ts`); `src/game/rulesGuard.test.ts` fails when one is missed and prints the digests to pin. Keep the state plain data (objects, arrays, `Map`, `Set`, numbers, strings, the run's `SeededRng`): `game/snapshot.ts` walks it structurally for co-op snapshots and hashes and throws on anything else; a cache goes in its `DERIVED`. `npm run determinism` checks the same runs hash the same in Node, Chromium, Firefox and WebKit.
- **Sealed grid** (`engine/spatial.ts`): the hitboxes' hits (`collide`, `pullFoes` in `game/attacks.ts`) read the spatial grid sealed (`sealBounds`, for the length of `updateAttacks`): each cell knows the box its foes stand in, so a cell out of reach goes unread, and overlaps are tested from the grid's copy of each foe's x, y and radius (`xs`, `ys`, `rs`). The cells and their order stay `query`'s, so it ends bit-identical only while every foe moved during `updateAttacks` tells the grid (`widen`, as `pullFoes` does), or is `movesOnItsOwn` (bosses, fight partners, Arena avatars: their cells are always read, and they are read again). New code that moves a foe during `updateAttacks` calls `widen`.
- **Players:** per-player state lives on `Player` (`Game.players`, one solo), never on `Game`. Per-player code reads `g.player` (the player acting, `actAs`); world code picks a player through `src/game/players.ts` (`nearestPlayer`, `anchorPlayer`, `playerWithin`, `onAnyScreen`) and must give the one player solo without touching the rng; a pick phase goes through `setPhase`/`phaseOf`; scans of `g.attacks` for a player's own hitboxes filter with `ownAttack`. The simulation never writes `g.camera`: it moves players' screens (`aimScreen`, `centerScreen`; players[0]'s is the drawn camera), and rooms set the whole team down with `placeTeam`. The shell reads its player with `localPlayer(g)`. Co-op (`g.coop`, null solo) adds rules in `src/game/coop.ts` and the tick driver in `src/game/lockstep.ts`; guard every co-op branch with `g.coop !== null` so solo stays bit-identical, keep co-op state plain data (snapshots serialize it), and give any new shell action a `TickEntry`.
- **Arena (code: Versus):** a Unite-style match in a format (`ARENA_FORMATS` in `src/data/arenaFormats.ts`, import-free for the relay; what each plays like in `VERSUS_FORMATS`: 4v4 on the Vale or the Enseada in 7 min, 3v3 on the Clareira or the Recife in 3 min) (`src/game/versus.ts`, numbers and roster in `src/data/versus.ts`, maps in `src/data/versusMaps.ts`: a new map of the same shape is an entry in `MAPS` with its `look` (whose `theme` picks the painter's scenery and the PixelLab set, `meadow` or `coast`) and in its format's `maps`; a match plays the room's `map` setting or one drawn from the seed, `matchMap`, so the queue needs no map; read the match's map and rules through `mapOf`/`rulesOf`, never a map directly) that runs on the co-op lockstep (`g.coop` set, plus `g.versus`; `Player.versus` per seat, both absent elsewhere, so solo and co-op never see them). A room's `mode: 'versus'` setting (`coop/start.ts`) starts one; solo matches play against bots through the in-page relay (`coop/localRelay.ts`). Seats no human takes are bots the simulation drives (`versusBots.ts`), so every client plays them the same. PvP goes through avatars: every Pokémon has an `Enemy` body (`behavior.kind === 'avatar'`, `versusCombat.ts`) that the rival team's moves hit like any foe and that routes the hit to its player; moves skip their own team's (`isAlly` where hitboxes collide and moves aim), the shell never draws them. Fair Play and the protection meter are the API's, from the relay's reports only (`game/arenaRank.ts`, numbers in `ARENA_RANKED`; the sim only counts each human's longest idle stretch, `VersusSeat.afk`; a new tick entry decides whether it's playing in `acts`: casts and locks are, chat, pings and votes aren't), and the matchmaker enforces them from the ticket lookup. `stepVersus` replaces `stepTeam` (the lockstep dispatches): only the systems a match needs run, the map is a `Room` (`roomOf`), and pick screens there neither hold the world nor take the Pokémon out of play (`inPlay`, `setPhase`). Quick chat, pings and the surrender vote (`versusSocial.ts`) are tick entries too: the simulation holds their rate limits and keeps the lines and pings as plain data on `g.versus` (no rule reads them), so every client shows the same; send message ids, never text. The shell's side is `ui/versusTalk.ts` (and the scoreboard, `ui/versusBoard.ts`). The gem shop's Arena-only cosmetics (spawn, KO and goal effects, emotes; see **Cosmetics**) play from the moments the match already announces (a goal, a KO, a respawn), and the emote is the one that reaches the match, as an `emote` tick entry with no payload (the seat's look picks the animation, so no cosmetic id ever enters the simulation; it isn't playing for `acts`). Its extra SpriteCollab animations are only the roster's front rows (`scripts/fetch-emotes.mjs`, part of `npm run assets`). The kit plays like Unite (`versusKit.ts`, numbers in `VERSUS_KIT`): the first move is the basic attack, cast on its own at the lock or the best rival by priority; Move 1, Move 2 and the Unite Move (the special) wait for `cast` tick entries aimed on the client (`ui/arenaControls.ts`, `ui/arenaAim.ts`). A cast turns the Pokémon (`VersusSeat.hold`) and sets a focus for its call that `nearestEnemy` answers from, so a move aims right without touching it; Move 2 and the evolutions' move swaps are `versusPacing.ts`, at the format's levels (`FormatRules.evolveAt`); a move that lasts on its own in a run (an aura, a trail) lasts `VERSUS_KIT.persist` per cast.
- **Cosmetics** (`data/cosmetics.ts`, bought with gems in the gem shop, `ui/gemShop.ts`; skins have their own page, see **Skins**): looks only, never power, and never in `src/game` (the shell's state, `render/looks.ts`; `RULES_VERSION`, replays and co-op hashes never see them). They show in every mode, slot by slot (`SLOT_MODES`: worn items, the trail, the title and the plate in runs, solo and co-op, the Dojo and Legend mode too, and in the Arena; the spawn, KO and goal effects and the emote in the Arena only, which the shop tags, `arenaOnly`); whatever draws a seat reads `shownLook(g, seat)`, its look as the game's mode shows it (`lookOf` is the whole look, for the Arena's screens). A solo run wears the account's own look (`equippedLook`, owned only); a room, co-op or Arena, wears only what the API vouches for: the relay plays a queue match's from the ticket lookup and asks `POST /looks` (`net/looks.ts`) as any friends' room starts (a failure plays bare), and a client's own loadout look only previews on its own screen. The effects (`render/arenaFx.ts`: trails, the Arena's bursts and emotes) step on the drawing clock; a lean frame (`render/quality.ts`) halves their particles and, in a run, leaves teammates' trails out. No follower cosmetics: a Pokémon walking along is the supporters' companion (`render/companion.ts`), never sold, and many of those species are playable. Gems are earned only where the API trusts the result (relay-confirmed Arena matches, Patreon, packs), never from a run.
- **Wearables** (hats and a balloon; `WEARABLES` in `src/data/wearables.ts`, the gem shop's worn cosmetics): each is a small 3D model in `render/wearModels.ts` (signed distances around its slot's pivot, with an occluder for the head) that `render/wearArt.ts` renders into PMD-style pixel art (four-tone ramps, a dark outline) for 5 directions, the other 3 mirrored, in a worker (`render/wearWorker.ts`). `render/wearables.ts`'s `drawDressed` (in `drawPlayer`'s place of `drawPokemon`, in every mode, from `shownLook`, and the Boutique's preview) draws the frame dressed: the worker dresses each sheet row (`render/wearDress.ts`) from the variant's head rig, made by `npm run rig` (`render/wearRig.ts`: each direction's head read once on the Walk frame the others agree with, the seat on the skull once thin ears, horns, lobes of other colors and side lobes are left out, the eyes, the neck and the back, from the sprite's pixels and its SpriteCollab offsets, then tracked into every frame of Walk, Idle and Hurt so a hat rides the head) into `data/wearRig/` for every species and form a player can be (`PLAYERS` and `FORMS` in `scripts/dex.mjs`), a file per 32 dex numbers that the engine loads as a species first wears something (`rigChunk`, keyed by `rigKey`). The dresser sizes each model from the rig (a hat to each direction's skull), keeps a row of the face between a hat and the eyes (lifting it clear before cutting its brim), keeps what wraps the head (`HUG` parts) inside its outline, lets what grows from the head show through open items, and runs one outline round the whole; an animated item's moving part plays over the dressed frame. What the rig gets wrong is fixed by hand in `data/wearFits.ts` (`rig` fixes per direction, per anim or per anim facing one way, per eye; a shiny with its own sheets by `'<dex>s'`; made and printed by `ps.rig(dex)`; `no` per slot, item or direction only as a last resort, with its reason). A change to how the rig reads heads moves the fixes with it: `npm run rig:migrate -- --from <ref of the old rig>` after `npm run rig`. `npm run fit-check` dresses every item on every variant in every direction on every frame and judges what's drawn from masks: by the rig drawn (an eye covered, a hat floating or sunk, a back item at head height) and by the silhouette, which doesn't trust the rig (a hat on the face's details; a seat sunk into the skull or on a tip only as suspects to look at): run it after touching models, the rig or the fixes. Only the sheets the rig measured wear a look (`rigSheet` in `render/wearFit.ts`): a variant's own Walk, Idle and Hurt (a Mega with sheets has its own; one without stands in with its final stage's sprite and rig; a legend shrunk to size wears its rig shrunk with it). Anything else draws bare, never the whole sprite hidden: a variant without offsets, a species until its chunk lands or its rows are dressed, the sky's Fly sheet, and the moments `drawPlayer` marks bare (an emote, a Mega's transformation, a move's own look like Fly or Dig); the evolution scene and the legends' scenes draw their own sprites, bare. A new item is an entry in `WEARABLES`, a model and its names in `wearables` (i18n); look at it on the roster with `ps.wear('fit', id)` and `npm run fit-check -- --items <id>` before shipping it, and judge it on every Pokémon by eye too: on 2026-11-01 the glasses, the neck items and the capes, wings and packs were cut from the launch because they didn't look right on enough Pokémon (git history has them).
- **Skins and the Ateliê**: a skin is a species line's Walk/Idle/Hurt sheets redrawn, one variant per evolution stage, sold in the gem shop (one buy dresses every stage it covers). Only keyframes are drawn (a frame per direction, plus one per pose too far from it: a jump, a crouch); `src/skins/propagate.ts` dresses every other frame by following the sprite's motion, and fixes touch up single frames. A skin that only recolors colors nothing else uses (a season's leaves, a palette theme) is a variant's `recolor` map instead, with no keyframes. Sources are palette-letter grids in `src/data/skins/<id>.json`; the baked sheets in `public/assets/skins/<id>/<dex>/` (the shiny's in `shiny/` below) come from them (`npm run skins`), never edited by hand. Draw in the Ateliê (`/atelier/` on the dev server, never built) or from a terminal (`npm run skin -- <command>`, `scripts/skinAuthor.mjs`). A garment always shows where it ends (a collar at the nape, cuffs, a hem where a tail comes out), and nothing covers the eyes or the mouth. A skin becomes a catalog item with an entry in `SKINS` (`data/skinCatalog.ts`: its `line`, the `dexes` its source covers, rarity and price, `season` for a series; `skinCatalog.test.ts` checks it against the source and the baked sheets), its name in i18n `skins`, and, for a series, its bundles in `SKIN_BUNDLES` (a bundle costs what its missing items' share of its price is, `bundlePrice`; the API grants it whole, `POST /gems/bundle`). It isn't a slot: a `Look` holds `skins`, at most one per line (`equip`, `skinFor`), owned-checked by the API like the slots and carried by the relays in vouched looks. It's drawn wherever a seat's Pokémon is (`playerSprites` in `render/legend.ts`, teammates' `mateSprites`): `skinFor(shownLook(g, seat), dex)` picks the skin for the species on screen and `skinSprites` (`render/sprites.ts`) loads its sheets laid out as the species' own, so the head rig dresses them too (the wearables dress a skin's rows apart, `SpeciesSprites.skin`); a Mega, a legend's form or a stance draws the species' own sheets, and the sky's Fly is the species' own. The Boutique's Skins tab is `ui/skinShop.ts`; Visual wears one per line.
- **Biomes are places on the map, not times:** the map is a patchwork of biome regions (`BIOME_MAP` in `src/data/biomes.ts`), a pure function of the run's terrain seed and a spot (`biomeAt`/`sampleBiome`/`biomeOf` in `src/game/biomeMap.ts`, the one lookup). A player's biome is `Player.biome` (`game/biomes.ts`; held inside rooms), the sky follows the lead's (`leadBiome`), a terrain feature wears its cell's (`Feature.biome`). Never keep a run-wide biome. A new biome needs an entry in every `Record<BiomeId, …>` (ground, terrain, landmark and prop skins, minimap, music, hazards, Judgment) and a tier in `BIOME_TIERS`.
- **Grande Atualização families, batch B** (`data/gaFamiliesB.ts`): Onix, Happiny, Clauncher, Fletchling, Golett, Nacli, Inkay, Skorupi, Snover, Tynamo, Dewpider, Duraludon, Bounsweet, Sandile and Stufful's lines, each with a mechanic of its own on `Player.kitB` (absent for everyone else, so other runs stay bit-identical): numbers and pure rules in `game/gaKitBRules.ts` (`KIT_B`, by evolution stage), the per-tick system and the `hurtPlayer`/`killEnemy` hooks in `game/gaKitBSystem.ts`, the signatures in `game/gaKitBMoves.ts` with their steps in `game/gaKitBUpgrades.ts` (data only: `i18n/gaFamiliesB.ts` builds every language's level-up lines from it), the look in `render/gaKitBFx.ts` and `render/gaKitBArt.ts`. As in Temporada 1, every bonus is capped and every protection (Water Bubble, the arm jets' flight) has a fixed cooldown and claims the ward (`wardOpens`). Onix's body is a chain (`stepSerpent`: pulled along, never pushed, coiled round the head once it stands still) drawn in its sheets' own ramp (`segmentSprite`, shiny and Mega too). Sandile dives through the move kit's `burrow` (hidden under `powerTrip`, so the foes lose it) and erupts as it surfaces; its Moxie stacks on any KO. Stufful's hug holds a foe by id on the kit and hurls it with `throwFoe`. Happiny's eggs heal any player who walks over them (co-op too). Spark's latch (Tynamo's line) rides its move: a `tether` hitbox whose shocks arc in `onHit`. Mega Steelix and Mega Eelektross are in `MEGAS`. Litleo (Pyroar has no SpriteCollab sheets) and Cufant (Copperajah has no Hurt sheet, Cufant no shiny) were left out until SpriteCollab has them; Sandile and Stufful took their places. A species shiny SpriteCollab lacks can be a palette swap of its own sheets (`RECOLORED_SHINIES` in `scripts/dex.mjs`, Naclstack's), made by `npm run assets` and credited as its artist's work recolored.
- **Epic rifts:** a rift legendary's whole rift is data: its domain in `src/data/domains/<legend>.ts` (the doc block atop `src/data/domains.ts` explains how to author one; Kyogre's is the reference), its phases' patterns built from the boss primitives in `data/bosses.ts`, and hooks (`game/domainHooks.ts`) only for what data can't say. The run clock (`g.time`) stops inside a rift; anything that needs a never-paused clock (hit cooldowns, ages, animation) uses `g.now`.
- **Moves:** `MOVES` (`src/game/moves.ts`) spreads in tables that live in their own modules (`signatureMoves.ts`, `eggMoves2.ts`, `tmMoves.ts`, `verbEvolutions.ts`, `duoMoves.ts`, `legendaryMoves.ts`, `shopTmMoves.ts` and its second batch `shopTmMoves2.ts`, Ponyta's gallop batch `gallopMoves.ts`); a new batch gets its own module, built on the move kit (`moveKit.ts`, `moveHooks.ts`), and goes in `MOVE_TABLES` too (`moveTables.test.ts` fails when an id is in two tables: the later spread would silently win). Every base move has forks at Lv 4 and Lv 7 (`{ fork: [A, B] }` in `upgrades`), each branch with a behavior mod (`mods.ts`). Signature, legendary, duo and TM moves (the shop-exclusive ones too) never evolve (`neverEvolves` in `src/data/evolutions.ts`); every other base move has an evolution. Learnsets are per evolution stage (`src/game/learnsets.ts`, `PlayableDef.learnset`, plus a branch's own moves).
- **Simulation ≠ presentation.** `src/game/*` must not touch the DOM or audio. Notify the shell by pushing a `GameEvent`; `main.ts` handles sounds, cries and toasts.
- **Pixel-perfect rendering.** The world is drawn at low internal resolution and integer-upscaled. Snap draw positions to whole pixels and use the hard-edged helpers in `engine/pixelart.ts`. New effect art is code-authored pixel strings (`render/art.ts`).
- **Five languages: pt-BR, English, Spanish (Latin America), French and Traditional Chinese (`zh`, Taiwan and Hong Kong).** Every player-facing string lives in `src/i18n` (`pt.ts` is the reference; `en.ts`, `es.ts`, `fr.ts` and `zh.ts` must match it key for key, and the type checker enforces it, down to one line per move upgrade). The UI is in Jersey 10 (`--title`) and Jersey 15 (`--body`), with VT323 filling in the ₽ and ↑ ↓ they lack; both have accented capitals, so new French ALL-CAPS labels keep their accents (older ones in `fr.ts` were written without them for Press Start 2P, which now only draws the logo and the Realm's mini games); Chinese is drawn in Cubic 11 (`public/fonts/cubic-11`, loaded only for CJK text). The changelog requires pt/en/es and falls back to English in fr/zh (`site/localized.ts`); give the newest update's highlights fr and zh too, since the lobby's Novidades shows them. Read text with `t()` at render time, never at module load. Pokémon, move and item names stay in English (official names) and live in the data files.
- **Comments:** short doc comments above non-obvious functions. Don't comment every line, and keep comments in sync with the code.
- **Tests:** focused vitest tests for pure rules only (`*.test.ts`). No smoke or snapshot slop.
- **SEO/GEO copy** lives in static HTML so crawlers and AI chats can read it without JS: `index.html` (pt-BR, `/`), `en/index.html` (English, `/en/`), `es/index.html` (Spanish, `/es/`), `fr/index.html` (French, `/fr/`), `zh-tw/index.html` (Traditional Chinese, `/zh-tw/`) and `public/llms.txt`. When a feature changes what the game is (starters, bosses, counts), update all six. Two site pages answer searches for the look-alike games (`ROUTES.compare`, `ROUTES.alternatives`, data in `src/site/rivals.ts`): their facts about the other games are dated (`RIVALS_CHECKED`), so recheck them against those games' sites when you touch either page.
- **Site pages** (`/pokedex/`, `/guia/`, `/novidades/`, `/legal/` and their `/en/` and `/es/` twins) are rendered at build time from `src/site` (wired in `vite.config.ts`) and read `src/data/*`, so the Pokédex and the guide's tables follow the data on their own. Their copy lives in `src/i18n/site` (`pt.ts` is the reference). Routes live in `src/site/routes.ts`, which also generates `sitemap.xml`. The Criadores page (`ROUTES.creators`) lists creators and their videos from `src/data/creators.ts`: a new video is its URL in `CREATOR_VIDEOS` plus `npm run creators`, and the creator's reward (the `creator` title and frame) goes from the admin desk. When a player-facing change ships, add it to `src/site/changelog.ts`: a change in today's update (revisit its 3 to 5 highlights, which the lobby's Novidades shows) or a new update on top, one per day, no PR links (players read it). `src/site/client.ts` must never import game code, so the game and the site never load each other's bundles.
- **Largar item** (`game/itemDrop.ts`): a player lets go of a held item mid-run, no refund: from the pause menu (tap an item, then confirm) or to swap one out when a new item's card (a level-up's or a Poké Ball's) comes with every slot taken (`needsSwap`; `ui/itemSwap.ts` asks which goes). A full build is offered a maxed base move's missing pair item as a swap (`swapItems`), always beside a berry when the swaps are the only cards; a dropped item, or a swap card turned down, sits out the offers for `DROP_REST` level-ups (`Player.dropped`, `restingItems`). The shell records the drop (`drop` replay event, a `drop` tick entry in co-op) before the pick that follows; `applyOffer` never fills past `MAX_ITEMS`. The Dojo drops through `setItem`.
- **Evolution items** (`EVO_ITEMS` in `src/data/shop.ts`): a branch an item names needs that item in a run, owned (`ReplayStart.evo`) or found (a boss's drop, `game/evoGate.ts`, chance in `EVO_FIND`), unless the branch is `free` (Eevee's three stones only add theirs to the choice). `evolutionOffers` (`game/branch.ts`) decides: no way open holds the evolution (`Game.evoHeld`, Everstone-strong), one way evolves without asking, more opens the pick.
- **Legends** (`src/data/legends.ts`, Legend mode only) are in `PLAYABLE`/`PlayableId` but not in `PLAYABLE_IDS` (the regular cast, which the Desafio do dia draws from). A `PlayableId` that isn't a hatchling may be a legend: test `isStarter`, never `!isHatchling`. A legend has one stage and awakens instead of evolving (`src/game/legend.ts`); its difficulty multipliers come from `runMods(g)`, not `DIFFICULTIES` directly.
- **Legends with a road of their own** (`QUEST_LEGENDS` in `src/data/legends.ts`, out of `REGULAR_LEGENDS`: Arceus never waits for them), each caught its own way (`LegendUnlock`, `legendSource` in `game/capture.ts`): Palkia in its epic rift (`data/domains/palkia.ts`: twin portals over the crossing's gaps, `Crossing.portals`, that space twists to lead back; a hall that wraps east to west, Palkia swapping places with the player, Origin Forme folding the walls in, its transformation cracking the frame and its last Spacial Rend tearing it in two; hooks in `game/palkiaDomain.ts`, looks in `render/palkia.ts`); the roaming lake trio (`game/roamers.ts`) and the Swords of Justice's duels (`game/duels.ts`; the duel's card under the boss bar, `createDuelCard` in `ui/quests.ts`, and its clock on the ring), the open map's legends, numbers in `data/quests.ts`, drawn from the run's seed apart from its rng (`game/quests.ts`) and only from what the save still has to catch (`ReplayStart.wild`, `wildOf` in `game/questSave.ts`), solo only (`COOP_LOCKS.quests`); a roamer's HP share carries over in `Save.roamers` (banked by the shell from its `roam` events and as the run ends; merged by the lower share), its body an `Enemy` with `behavior: 'roam'` that `updateBosses` never fights with; Keldeo and the Mestre do Tempo e do Espaço title are game-made gifts (`game/questGifts.ts`); Hoopa's Rings (`game/rush.ts`, `data/rush.ts`), the Legend mode's boss rush from the Lendários tab's banner: a run with no horde on Hoopa's own stage (`g.rush`, a room, `RushState.room`, drawn by `drawRushFloor` in `render/rush.ts`; its own tick `stepRush`, like the Dojo never ranked, banked nor replayed: each player's lineup follows their own captures, so it has no board, only each level's best time, `Save.rush`), whose rings bring back the captured legends with the same HP whatever their species and end on Hoopa (caught on the first clear). A fight that needs its boss in view (a rift's battle, the rings, a duel) takes the run's news one line at a time, off the top (`focusToasts` in `ui/toasts.ts`); a phase that changes a boss's form plays the change in a white flash (`formChangeAt`, `bossForm` in `render/legendFx.ts`) with the screen kept on the boss (`domainCamera`). Their moves are the third batch of legendary moves (`game/legendaryMoves3.ts`, art in `render/legendaryFx3.ts`; the lake trio and the Swords share theirs, as in the games), their words `src/i18n/quests.ts`.
- **Map archetypes** (`src/data/mapArchetypes.ts`): each run draws one from its seed (`archetypeOf`, `runArchetype` in `game/terrain.ts`) and it only weighs what the cells hold; every new shape keeps the terrain's rules (one feature per cell, off its edges, the start clear) and is drawn by a skin every biome already has (ridges as `cliff`, bays as `lake`, thickets as trees, colonnades as the ruins' pieces), so a new biome only needs those. `src/game/mapArchetypes.test.ts` floods every archetype from the start. Traversal by type (`TRAVERSAL` in `game/terrain.ts`: Water surfs, Flying hovers, Ice skates, Ghost phases through `THIN_SOLIDS`) is per player, only on the open map (never in an Arena match, a Dojo session or a room), and never touches the horde's pace.
- **The National Dex** (`data/nationalDex.ts`, `game/dexRegions.ts`): the horde is every regular species SpriteCollab has full sheets for, normal and shiny (`npm run roster` builds it from PokeAPI's CSVs, `scripts/pokeapi.mjs`; never legendaries, mythicals, Ultra Beasts, Paradox Pokémon, the starters' lines or species kept out in `KEPT_OUT`; a new species heavier than `HEAVY` stays out), and a run still holds only its cast: a species' draw odds are its capture rate's (`rarityOf`, `EnemyDef.rarity`), so more species never means more sheets at once (a cast-wide lean towards biomes the cast doesn't cover was tried and dropped: it favored slow Rock and Ground species, whose endless flybys piled up past `ENDLESS_HORDE.ceiling`). `npm run roster` also writes `nationalDex.generated.json`: the mythicals and the species SpriteCollab hasn't drawn yet, which the Pokédex (in game, `ui/pokedex.ts`, and on the site, `/pokedex/<region>/`) shows as a thank-you card with a link to help draw them. Each region's Pokédex asks for its species in `GAME_SPECIES` but the mythicals and the event legends (`dexGoal`): seeing them all brings its title, every region the National Dex frame, as game-made gifts (`dex:<region>`, vouched once applied, so a goal that grows later never takes one back). Seen, not caught: a wild species is caught only by defeating a shiny.
