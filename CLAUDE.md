# Pokémon Survivors – agent guide

Browser survivors-like (Vampire Survivors–style) with Pokémon. Vite + TypeScript + Canvas 2D, no engine. Read `README.md` for the architecture map.

## Conventions

- **Functional TypeScript only.** Use plain data (types/records) and functions. No classes or `this`. Never use `any`. Prefer inferred types and `as const satisfies` data tables, and keep content data-driven (`src/data/*`, `MOVES` in `src/game/moves.ts`).
- The simulation mutates plain state for performance (hundreds of entities at 60 Hz), and that's fine. Keep hot loops allocation-light (see `retain`, the spatial grid).
- **The simulation is deterministic**: the server re-simulates ranked runs from their replay (`src/game/replay.ts`) and must land on the same bits. In `src/game` (and anything it computes from `src/data`) use the seeded rng, never `Math.random` or the clock; use `engine/dmath` (`dm.sin`, `dm.cos`, `dm.atan2`, `dm.hypot`, `dm.exp`, `dm.pow`, `dm.sq`, `dm.round`) instead of `Math.sin/cos/atan2/hypot/exp/round`, `**` or `Math.pow`, which differ between JS engines (Safari's JIT rounds 0.49999999999999994 up; `src/engine/dmathGuard.test.ts` fails on any of them in the sim); size hitboxes from `bodyOf` (data), never from loaded sprites. Anything new the shell does to a running game (a pick, a button) goes through `recordEvent` and gets a case in `resimulate`. A change that makes the same inputs end elsewhere bumps `RULES_VERSION` (`replay.ts`); `src/game/rulesGuard.test.ts` fails when one is missed and prints the digests to pin. Keep the state plain data (objects, arrays, `Map`, `Set`, numbers, strings, the run's `SeededRng`): `game/snapshot.ts` walks it structurally for co-op snapshots and hashes and throws on anything else; a cache goes in its `DERIVED`. `npm run determinism` checks the same runs hash the same in Node, Chromium, Firefox and WebKit.
- **Players:** per-player state lives on `Player` (`Game.players`, one solo), never on `Game`. Per-player code reads `g.player` (the player acting, `actAs`); world code picks a player through `src/game/players.ts` (`nearestPlayer`, `anchorPlayer`, `playerWithin`, `onAnyScreen`) and must give the one player solo without touching the rng; a pick phase goes through `setPhase`/`phaseOf`; scans of `g.attacks` for a player's own hitboxes filter with `ownAttack`. The simulation never writes `g.camera`: it moves players' screens (`aimScreen`, `centerScreen`; players[0]'s is the drawn camera), and rooms set the whole team down with `placeTeam`. The shell reads its player with `localPlayer(g)`. Co-op (`g.coop`, null solo) adds rules in `src/game/coop.ts` and the tick driver in `src/game/lockstep.ts`; guard every co-op branch with `g.coop !== null` so solo stays bit-identical, keep co-op state plain data (snapshots serialize it), and give any new shell action a `TickEntry`.
- **Arena (code: Versus):** a Unite-style match in a format (`ARENA_FORMATS` in `src/data/arenaFormats.ts`, import-free for the relay; what each plays like in `VERSUS_FORMATS`: 4v4 on the Vale in 7 min, 3v3 on the Clareira in 3 min) (`src/game/versus.ts`, numbers and roster in `src/data/versus.ts`, maps in `src/data/versusMaps.ts`: a new map of the same shape is an entry in `MAPS` with its `look`; read the match's map and rules through `mapOf`/`rulesOf`, never a map directly) that runs on the co-op lockstep (`g.coop` set, plus `g.versus`; `Player.versus` per seat, both absent elsewhere, so solo and co-op never see them). A room's `mode: 'versus'` setting (`coop/start.ts`) starts one; solo matches play against bots through the in-page relay (`coop/localRelay.ts`). Seats no human takes are bots the simulation drives (`versusBots.ts`), so every client plays them the same. PvP goes through avatars: every Pokémon has an `Enemy` body (`behavior.kind === 'avatar'`, `versusCombat.ts`) that the rival team's moves hit like any foe and that routes the hit to its player; moves skip their own team's (`isAlly` where hitboxes collide and moves aim), the shell never draws them. Fair Play and the protection meter are the API's, from the relay's reports only (`game/arenaRank.ts`, numbers in `ARENA_RANKED`; the sim only counts each human's longest idle stretch, `VersusSeat.afk`; a new tick entry decides whether it's playing in `acts`: casts and locks are, chat, pings and votes aren't), and the matchmaker enforces them from the ticket lookup. `stepVersus` replaces `stepTeam` (the lockstep dispatches): only the systems a match needs run, the map is a `Room` (`roomOf`), and pick screens there neither hold the world nor take the Pokémon out of play (`inPlay`, `setPhase`). Quick chat, pings and the surrender vote (`versusSocial.ts`) are tick entries too: the simulation holds their rate limits and keeps the lines and pings as plain data on `g.versus` (no rule reads them), so every client shows the same; send message ids, never text. The shell's side is `ui/versusTalk.ts` (and the scoreboard, `ui/versusBoard.ts`). The gem shop's cosmetics are looks only (`data/arenaCosmetics.ts`): the shell draws a seat's (`lookOf`, `render/arenaFx.ts`) from the moments the match already announces (a goal, a KO, a respawn), and the emote is the one that reaches the match, as an `emote` tick entry with no payload (the seat's look picks the animation, so no cosmetic id ever enters the simulation; it isn't playing for `acts`). Its extra SpriteCollab animations are only the roster's front rows (`scripts/fetch-emotes.mjs`, part of `npm run assets`). The kit plays like Unite (`versusKit.ts`, numbers in `VERSUS_KIT`): the first move is the basic attack, cast on its own at the lock or the best rival by priority; Move 1, Move 2 and the Unite Move (the special) wait for `cast` tick entries aimed on the client (`ui/arenaControls.ts`, `ui/arenaAim.ts`). A cast turns the Pokémon (`VersusSeat.hold`) and sets a focus for its call that `nearestEnemy` answers from, so a move aims right without touching it; Move 2 and the evolutions' move swaps are `versusPacing.ts`, at the format's levels (`FormatRules.evolveAt`); a move that lasts on its own in a run (an aura, a trail) lasts `VERSUS_KIT.persist` per cast.
- **Epic rifts:** a rift legendary's whole rift is data: its domain in `src/data/domains/<legend>.ts` (the doc block atop `src/data/domains.ts` explains how to author one; Kyogre's is the reference), its phases' patterns built from the boss primitives in `data/bosses.ts`, and hooks (`game/domainHooks.ts`) only for what data can't say. The run clock (`g.time`) stops inside a rift; anything that needs a never-paused clock (hit cooldowns, ages, animation) uses `g.now`.
- **Moves:** `MOVES` (`src/game/moves.ts`) spreads in tables that live in their own modules (`signatureMoves.ts`, `eggMoves2.ts`, `tmMoves.ts`, `verbEvolutions.ts`, `duoMoves.ts`, `legendaryMoves.ts`, `shopTmMoves.ts` and its second batch `shopTmMoves2.ts`); a new batch gets its own module, built on the move kit (`moveKit.ts`, `moveHooks.ts`). Every base move has forks at Lv 4 and Lv 7 (`{ fork: [A, B] }` in `upgrades`), each branch with a behavior mod (`mods.ts`). Signature, legendary, duo and TM moves (the shop-exclusive ones too) never evolve (`neverEvolves` in `src/data/evolutions.ts`); every other base move has an evolution. Learnsets are per evolution stage (`src/game/learnsets.ts`, `PlayableDef.learnset`, plus a branch's own moves).
- **Simulation ≠ presentation.** `src/game/*` must not touch the DOM or audio. Notify the shell by pushing a `GameEvent`; `main.ts` handles sounds, cries and toasts.
- **Pixel-perfect rendering.** The world is drawn at low internal resolution and integer-upscaled. Snap draw positions to whole pixels and use the hard-edged helpers in `engine/pixelart.ts`. New effect art is code-authored pixel strings (`render/art.ts`).
- **Five languages: pt-BR, English, Spanish (Latin America), French and Traditional Chinese (`zh`, Taiwan and Hong Kong).** Every player-facing string lives in `src/i18n` (`pt.ts` is the reference; `en.ts`, `es.ts`, `fr.ts` and `zh.ts` must match it key for key, and the type checker enforces it, down to one line per move upgrade). French ALL-CAPS labels drop their accents (Press Start 2P has no accented capitals); Chinese is drawn in Cubic 11 (`public/fonts/cubic-11`, loaded only for CJK text). The changelog requires pt/en/es and falls back to English in fr/zh (`site/localized.ts`); give the newest update's highlights fr and zh too, since the lobby's Novidades shows them. Read text with `t()` at render time, never at module load. Pokémon, move and item names stay in English (official names) and live in the data files.
- **Comments:** short doc comments above non-obvious functions. Don't comment every line, and keep comments in sync with the code.
- **Tests:** focused vitest tests for pure rules only (`*.test.ts`). No smoke or snapshot slop.
- **SEO/GEO copy** lives in static HTML so crawlers and AI chats can read it without JS: `index.html` (pt-BR, `/`), `en/index.html` (English, `/en/`), `es/index.html` (Spanish, `/es/`), `fr/index.html` (French, `/fr/`), `zh-tw/index.html` (Traditional Chinese, `/zh-tw/`) and `public/llms.txt`. When a feature changes what the game is (starters, bosses, counts), update all six. Two site pages answer searches for the look-alike games (`ROUTES.compare`, `ROUTES.alternatives`, data in `src/site/rivals.ts`): their facts about the other games are dated (`RIVALS_CHECKED`), so recheck them against those games' sites when you touch either page.
- **Site pages** (`/pokedex/`, `/guia/`, `/novidades/`, `/legal/` and their `/en/` and `/es/` twins) are rendered at build time from `src/site` (wired in `vite.config.ts`) and read `src/data/*`, so the Pokédex and the guide's tables follow the data on their own. Their copy lives in `src/i18n/site` (`pt.ts` is the reference). Routes live in `src/site/routes.ts`, which also generates `sitemap.xml`. When a player-facing change ships, add it to `src/site/changelog.ts`: a change in today's update (revisit its 3 to 5 highlights, which the lobby's Novidades shows) or a new update on top, one per day, no PR links (players read it). `src/site/client.ts` must never import game code, so the game and the site never load each other's bundles.
- **Evolution items** (`EVO_ITEMS` in `src/data/shop.ts`): a branch an item names needs that item in a run, owned (`ReplayStart.evo`) or found (a boss's drop, `game/evoGate.ts`, chance in `EVO_FIND`), unless the branch is `free` (Eevee's three stones only add theirs to the choice). `evolutionOffers` (`game/branch.ts`) decides: no way open holds the evolution (`Game.evoHeld`, Everstone-strong), one way evolves without asking, more opens the pick.
- **Legends** (`src/data/legends.ts`, Legend mode only) are in `PLAYABLE`/`PlayableId` but not in `PLAYABLE_IDS` (the regular cast, which the Desafio do dia draws from). A `PlayableId` that isn't a hatchling may be a legend: test `isStarter`, never `!isHatchling`. A legend has one stage and awakens instead of evolving (`src/game/legend.ts`); its difficulty multipliers come from `runMods(g)`, not `DIFFICULTIES` directly.
- **Plaza visitors** (`src/data/visitors.ts`): Meowth's weekend caravan, the loyalty card's milestones and the seasonal stalls are data. A new seasonal stall is an entry in `STALLS` (dates, keeper, `stall-<id>.png` art) and its lines in `plaza.stalls`. Rewards the game grants on its own (the candy jar, the loyalty card, the Tycoon's) are Mystery Gifts with the game's own ids (`game/gameGifts.ts`): they wait in the lobby's gift box, and the API keeps what they gave (`gameGiftsApplied`).
- **Festival da Praça** (`src/data/festivals.ts`): each festival is an entry (days, milestones with their gift and plaza stage). Only the API takes ₽ (`POST /festival/donate`, from the stored save into `spent`); the milestone gifts and the Mecenas title are game-made from `GET /festival` (`festivalGifts` in `game/festival.ts`, read on the device by `src/festival.ts`) and the API vouches for them on every push from its own sums (`festivalGiftsVouched`). The plaza draws `plazaStage`. The sheet is `openFestival(root, input, close)` (`ui/festival.ts`, laid out as the shop's `.shop-sheet`), opened from the lobby's Hoje card while one runs (`F`), and the shop's Festival button (`festivalAnnounced`: running or the day before).
- **Dojo** (`game/training.ts`): a training run is `Game.training !== null`; it steps through `stepTraining` and the shell changes it directly (it's never ranked, banked or replayed), so keep every training branch behind that check. Builds (`game/builds.ts`, the save's `builds`) only mark pick cards (`planned`): never let one change a run.
- **Estádio** (`render/stadium.ts`): the Arena's place in the lobby, south of home (the plaza is east, the Dojo west). Ninjask judges at the gate and the forecourt's boards lead to the Arena (Jogar) and its hub's tabs; like the plaza and the Dojo it's pure presentation, its talk spots a `LobbyNpc` and its trip a `ShopTrip` (`ui/title.ts`).
- **Mobile matters:** many players will be on phones. Every UI must work with touch and on small portrait and landscape screens.

## Commands

```bash
npm run dev        # vite dev server
npm test           # vitest
npm run build      # tsc --noEmit + vite build (must pass before any PR)
npm run roster     # rebuild the wild horde (curated list in scripts/roster.mjs) from PokeAPI + SpriteCollab
npm run assets     # fetch sprites (add new dex numbers in scripts/dex.mjs; the horde comes from the roster)
npm run credits    # regenerate CREDITS.md (SpriteCollab artists) after adding species
npm run bodies     # re-measure sprite bodies (hitboxes) into sprites.generated.json; `npm run assets` does it too
node --env-file=.env.local scripts/discord/pull.mjs    # snapshot the community Discord into scripts/discord/snapshot.json (read-only; commit it before and after any setup run)
node --env-file=.env.local scripts/discord/setup.mjs <step...> [--apply]   # pointed changes to the Discord (roles, channels, topics, community, messages, welcome, emojis, onboarding, automod); dry run by default. Staff edit names, order and looks by hand: the script only owns permissions and behavior, and finds things by id (ids.json). DISCORD_BOT_TOKEN, DISCORD_GUILD_ID
node --env-file=.env.local scripts/tierlist.mjs   # refresh the site's tier list snapshot (src/data/tierRuns.ts) from PostHog's run_end, last 30 days; POSTHOG_PERSONAL_API_KEY (or pass a CSV export of the same query). The build never queries PostHog
npm run typecheck --prefix server   # the accounts API (server/), typechecked with the shared game code
node scripts/indexnow.mjs --all   # tell Bing and the other IndexNow engines about every sitemap URL (after adding pages; production deploys ping the newest update's pages on their own, .github/workflows/indexnow.yml)
npm run determinism  # the same bot runs in Node, Chromium, Firefox and WebKit must hash the same (needs `npx playwright install`)
```

- **Accounts are optional.** Guest play (the local save) is the default and must never wait on the network. `src/account.ts` loads Clerk on demand and syncs the save to the API in `server/` (Hono + Postgres, deployed on Dokploy, see `server/README.md`). The merge rules (`mergeSaves`, `applyPush` in `src/game/sync.ts`) are shared by both sides: when a save field is added, give it a merge rule there. Without `VITE_CLERK_PUBLISHABLE_KEY` and `VITE_API_URL` the account button doesn't show.

- **Analytics and errors** go through `src/analytics.ts`: typed events (`AnalyticsEvents`) to PostHog (US cloud, behind the `/ingest` rewrite in `vercel.json`), only on production domains. PostHog's free tier is 1M events a month and the game plays thousands of runs a day, so summarize on `run_end` instead of adding per-pick or per-frame events. Uncaught errors are reported with the running game's replay; `ps.replay(json)` plays one again. Source maps upload at build (`scripts/sourcemaps.mjs`) where `POSTHOG_CLI_API_KEY` and `POSTHOG_CLI_PROJECT_ID` are set. To try it locally, set `VITE_POSTHOG_KEY` and run `localStorage.setItem('ps:analytics', 'on')`.
