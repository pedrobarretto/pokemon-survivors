# Frozen simulators

`rules-<N-1>.mjs` is the game's simulation as it was at `RULES_VERSION` N-1, one self-contained ESM file generated by `npm run rules:freeze` (`server/scripts/freeze-rules.mjs`). Don't edit it by hand. The API ships it so a ranked run that straddles a rules deploy is still taken and verified under the rules it was played by, instead of being refused as `outdated`.

## How it's used

- `POST /runs` pins the API's `RULES_VERSION` on the run's token (`runs.rules`, migration 022).
- `PUT /runs/:token` takes a replay of the previous rules only when its token is pinned to those same rules and was dealt at most `RULES_GRACE_SECONDS` ago (`server/src/rulesGrace.ts`: the longest run `RANKED.maxTime` allows, plus two hours). Anything older, and a replay that claims older rules than its token's pin, is still 400 `outdated`. The pin is the server's, so claiming old rules gains a cheater nothing.
- The checks' worker (`server/src/verify.ts`) re-simulates those runs with this bundle. It's imported on first use, and only in the worker (`server/src/sims.ts`), so boot and the request thread never load it.
- The Docker image copies it next to `dist/` (`/app/sims`).

Only one previous version is kept. Two bumps deployed within the grace window still refuse the runs two versions back.

## When you bump `RULES_VERSION`

1. Bump it in `src/game/replay.ts` and pin the new digests `rulesGuard.test.ts` prints.
2. Run `npm run rules:freeze`. It finds the code at N-1 (HEAD if the bump isn't committed, else `origin/main` when your branch sits on it, else the parent of the commit where N landed on HEAD's first-parent history), bundles it from a temporary `git worktree` with esbuild, writes `server/sims/rules-<N-1>.mjs` and deletes the previous one. The bundle's entry imports the game's modules in the order `server/src/sims.ts` does, since `src/game` has import cycles and the load order decides how they resolve; before writing, it checks the bundle's `MOVES` holds every move (a bundle that started from `replay.ts` lost the shop's TMs, and every replay with one armed threw in the worker).
3. Commit the new bundle with the bump. `server/src/sims.test.ts` fails until the bundle in this folder is exactly `RULES_VERSION - 1`.

Run it again after rebasing onto a newer `main`, so the bundle is built from the rules production actually plays.
